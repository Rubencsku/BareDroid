# BareDroid v1.0.1-munch — Rescue Console Fix

BareDroid v1.0.1-munch is a maintenance release for the Xiaomi POCO F4 / Redmi K40S (`munch`). It keeps the Linux 6.19.6 kernel, device tree and module set from v1.0.0 while correcting the Mainline initramfs rescue console.

This remains an experimental developer release, not a general-purpose phone installer.

## Fixed

- Mount `devpts` at `/dev/pts` before starting BusyBox `telnetd`.
- Fix the USB Telnet listener accepting a connection and immediately closing it because it could not allocate a pseudoterminal.
- Preserve a fallback `devpts` mount without options for reduced BusyBox or kernel configurations.

This fix restores the emergency Telnet shell. It does not add an SSH server to the initramfs. SSH on port 22 still depends on successfully mounting the root filesystem and starting its OpenSSH service.

## Reference stack

| Component | Version or implementation |
| --- | --- |
| Kernel | Linux 6.19.6 with `-munch-ubuntu` local version |
| Device tree | `sm8250-xiaomi-munch.dtb` with board ID `<50 0>` |
| Userspace target | Ubuntu 26.04 ARM64 minimal server |
| Init | systemd 259 in the reference rootfs |
| Wi-Fi | QCA6390 using `ath11k_pci` |
| Recovery network | USB Gadget Ethernet at `172.16.42.1/24` |

## Release assets

| File | Purpose |
| --- | --- |
| `debian_mainline_boot_munch.img` | Header-v3 boot image with the kernel and corrected ramdisk |
| `debian_mainline_vendor_boot_munch.img` | Header-v3 vendor boot image with DTB, command line and corrected vendor ramdisk |
| `debian_mainline_single_boot_munch.img` | Temporary-boot test image with appended DTB and corrected ramdisk |
| `Image-6.19.6-munch` | Uncompressed ARM64 kernel image |
| `sm8250-xiaomi-munch.dtb` | Compiled POCO F4 device tree |
| `modules-6.19.6-munch-ubuntu.tar.gz` | Matching Linux 6.19.6 kernel modules |
| `SHA256SUMS.txt` | Integrity hashes for every binary asset |

The release does not contain a complete Ubuntu root filesystem. Existing v1.0.0 installations can retain their current userdata/rootfs when updating the boot images.

## Verify downloads

Keep all downloaded assets in one directory and run:

```bash
sha256sum -c SHA256SUMS.txt
```

Do not boot or flash files that fail verification.

## Non-destructive test

Enter Fastboot mode and load the single image into RAM:

```bash
fastboot boot debian_mainline_single_boot_munch.img
```

After the USB gadget appears, test the corrected rescue console:

```bash
ping 172.16.42.1
telnet 172.16.42.1 23
```

## Update an existing v1.0.0 slot B installation

The update replaces only the slot-B boot-chain images. It does not require formatting userdata or reinstalling the root filesystem:

```bash
fastboot getvar product
fastboot getvar current-slot
fastboot flash boot_b debian_mainline_boot_munch.img
fastboot flash vendor_boot_b debian_mainline_vendor_boot_munch.img
fastboot --set-active=b
fastboot reboot
```

Confirm that `fastboot getvar product` reports `munch` before flashing. A fresh installation must follow the complete [installation guide](../installation.md), including its DTBO and rootfs preparation requirements.

## Security notice

The rescue Telnet service has no authentication or transport encryption. Use it only through a directly connected trusted USB cable. Do not bridge or share the gadget interface with another network.
